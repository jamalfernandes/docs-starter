## How to use this page

Copy the token block below into your repo as `tokens.css` and load it before anything else. Build every rule against the custom properties, never against raw values. Everything under the block is provenance: which file each number came from, how far we trust it, and what Xavier still has to confirm before a value is safe to ship.

<Note icon="file-search">
  Three sources feed this sheet, in this order of authority.

  1. **The live stylesheet, `xherman.com/assets/css/site.css?v=2.0`, read 7 October 2026.** Authoritative for `--font-*` and for the brand colours. This is the newest source and it overrides the other two wherever they disagree.
  2. **The 23 July Lighthouse capture.** Still useful for measured contrast ratios and class-usage counts. **Its font finding is obsolete** — it reported no webfont, and the site now self-hosts two.
  3. **The approved 4 September wireframe.** Authoritative for `--space-*`, `--scale-*`, radii, shadows and layout, none of which the live CSS contradicts.

  Where they disagree, the provenance table says which one wins.
</Note>

<Note icon="link">
  **The live stylesheet opens with a comment worth reading.** It names this kit as its own source, which means the two are not independent and should not be treated as cross-confirmation:

  ```text
  /* xherman.com — V2 stylesheet
     Source design: Boost33 homepage mockup v2 (30 Sept 2026)
     Tokens: Brand Kit /visual (orange #f95916 = action only,
     purple #451d9e = emphasis/focus only, slate neutrals).
     Fonts: Outfit (display) + Inter (UI), self-hosted, OFL. */
  ```

  His site was built from this page. When this page and his site agree on a colour, that is one decision recorded twice, not two sources agreeing.
</Note>

`#f95916` and `#451d9e` are the only two values that already agree across every Xavier property, so the palette is anchored on them. Everything else here is being decided for the first time.

**Usage rules.**

- Orange is the only action colour on this site. Purple never becomes a button.
- Orange never carries running text on white. Lighthouse measured `#f95916` on `#ffffff` at **3.24:1** and on `#f1f5f9` at **2.96:1**. Both fail the 4.5:1 body-text threshold. The live site uses orange for 12px mono labels anyway. Use `--color-accent-ink` for any orange text under 24px.
- White on orange also measured **3.24:1**. Orange-filled buttons need a dark label. The wireframe uses `#180600`, not white.
- Neutrals carry all text. Purple is for emphasis, borders and focus, not paragraphs.
- No value in `--color-night*` ever touches the page background. The dark bands are sections, not a theme. There is no dark mode anywhere in the estate and none is being designed.

## Typography

<Check icon="type">
  **Resolved 7 October 2026. The typeface question is closed, and it closed from the live site rather than from Xavier.**

  xherman.com now self-hosts **Outfit** for display and **Inter** for UI, both as variable woff2 under the SIL Open Font License, both preloaded in `<head>`:

  ```html
  <link rel="preload" href="/assets/fonts/outfit-latin-var.woff2" as="font" type="font/woff2" crossorigin>
  <link rel="preload" href="/assets/fonts/inter-latin-var.woff2"  as="font" type="font/woff2" crossorigin>
  ```

  Four files in all, latin and latin-ext for each family, declared `font-weight: 100 900; font-display: swap`. The unicode ranges match Google Fonts' own subsets exactly, so these are the Google variable files rehosted. His legal notice confirms it in writing: _"Polices Inter et Outfit sous licence SIL Open Font License."_

  Mono loads no webfont at all. The small uppercase labels render in the system mono stack, which differs per platform. That is faithful, not a bug.
</Check>

**What this supersedes.** The 23 July Lighthouse capture found no font file and concluded the site had no typeface. That was true of the site as it stood in July. It is not true now. Anything in an older draft that says "the live site has no typeface", or that treats Outfit as an unconfirmed recommendation, is superseded.

**Weight 650 is real and it needs the variable file.** The live site uses it on the primary button, on card titles and on several `strong` elements. With a static 600/700 pair it snaps to one or the other and the whole system reads subtly wrong. Ship the variable files, not static cuts.

<Warning icon="triangle-alert">
  **One thing on this page is now out of date and has not been rewritten.** The neutral ramp in the token sheet above is the Tailwind slate scale captured in July. The live stylesheet has since moved to its own values: `--ink #0b1220` for headings, `--ink-2 #2c384f` for body, `--ink-3 #475569`, `--ink-4 #556378`, `--line #e6eaf0`.

  They are close to the slate ramp but not identical. Reconciling them is a bigger change than Xavier's 7 October list asked for, and his instruction was explicitly to change nothing beyond it, so it has been left alone and flagged instead. **Before the build, pick one ramp.** The live site's own values are the safer choice, because that is what is already rendering.
</Warning>
