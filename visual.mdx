## How to use this page

Copy the token block below into your repo as `tokens.css` and load it before anything else. Build every rule against the custom properties, never against raw values. Everything under the block is provenance: which file each number came from, how far we trust it, and what Xavier still has to confirm before a value is safe to ship.

<Note>
Two sources feed this sheet. The **live xherman.com capture** (23 July 2026) is authoritative for `--font-*` and `--color-*`. The **approved 4 September wireframe** is authoritative for `--space-*`, `--scale-*`, radii, shadows and layout. Where they disagree, the provenance table says which one wins.
</Note>

`#f95916` and `#451d9e` are the only two values that already agree across every Xavier property, so the palette is anchored on them. Everything else here is being decided for the first time.

**Usage rules.**

- Orange is the only action colour on this site. Purple never becomes a button.
- Orange never carries running text on white. Lighthouse measured `#f95916` on `#ffffff` at **3.24:1** and on `#f1f5f9` at **2.96:1**. Both fail the 4.5:1 body-text threshold. The live site uses orange for 12px mono labels anyway. Use `--color-accent-ink` for any orange text under 24px.
- White on orange also measured **3.24:1**. Orange-filled buttons need a dark label. The wireframe uses `#180600`, not white.
- Neutrals carry all text. Purple is for emphasis, borders and focus, not paragraphs.
- No value in `--color-night*` ever touches the page background. The dark bands are sections, not a theme. There is no dark mode anywhere in the estate and none is being designed.

## Typography

<Warning>
**The live site has no typeface.** The 23 July capture loads no font file at all: no `@font-face`, no Google Fonts link, no font request in the network log. It loads Tailwind Play CDN, React 18, Babel Standalone, Lucide and Plausible, and nothing else. Every `font-sans` and `font-mono` class resolves to the browser default, so xherman.com renders in San Francisco on Mac, Segoe UI on Windows, Roboto on Android.
</Warning>

That null result is the answer. It is also why `--font-display` is `[awaiting Xavier]`.

**What the mockup rendered in, and why it is not evidence.** The 4 September wireframe declares `"Outfit"` for display and `"InterX"` for UI. Both `@font-face` rules resolve with `local()` only, so they picked up whatever was installed on the Boost33 machine. On the 4 September call Jamal flagged exactly this: the wireframe was rendering in Boost33 fonts, not Xavier's. Treat the mockup's letterforms as placeholder.

**Where "Outfit" actually comes from.** Not the capture. It is self-hosted as a variable TTF on `experiencehacking.eu`, alongside Inter, which that site uses for buttons only. It is the one real type choice anyone in the estate has made. Self-hosting it costs no new dependency and no Google CDN call. That suits the sovereignty positioning. So it is the candidate to beat. It is still a recommendation rather than a recovered fact, and Xavier has to say yes.

## Spacing and layout

The wireframe has no named spacing scale. It uses literal pixels, and they cluster tightly enough to ladder. `--space-1` through `--space-15` above is that ladder. The numbers are real, the naming is ours, and the row is marked inferred in the provenance table.

**Rhythm.** Sections run `112px` top and bottom, `64px` below 900px. The hero is the exception: `88px` top, `96px` bottom. Card grids gap `18px`. Two-column splits gap `54–64px`. Paragraph bottom margin is `18px`.

**Container.** `1160px` max width with `40px` gutters, `22px` below 900px. Reading measures are set in `ch`, not px, so they survive a font swap: `17ch` on H1, `19ch` on H2, `50ch` on the lede, `60ch` on body, `58ch` on pull quotes.

**Breakpoints.** The wireframe uses thirteen: 560, 640, 680, 720, 760, 860, 900, 940, 980, 1080, 1100, 1180, 1400. Only 900 moves global tokens. The four-step `--bp-*` set is a consolidation we propose, not something the file states. Build against it, then do one visual pass at the dropped widths.

**Grid columns.** Proof names `repeat(5,1fr)` → 3 at 720px. Stats `repeat(3,1fr)`. Offer cards `1fr 1fr` → 1 at 760px. Split sections `.4fr .6fr` → 1 at 900px. Qualify `.36fr .64fr` → 1 at 940px. Client wall `repeat(4,1fr)` → 2 at 860px.

## Component notes

<AccordionGroup>
<Accordion title="Proof strip" icon="layout-template">
A band, not a section. `--color-surface-sunken` with a 1px hairline top and bottom, `52px / 44px` padding, deliberately shorter than the sections around it. Two rows: client names on a 5-column grid at 20px display weight 600, then a `--line-2` rule, then three stats on a 3-column grid. First cell aligns left, last aligns right, middle centres. Stat number is `--scale-stat` at 700 with tabular figures; the label under it is 10px mono uppercase at `.12em`. The visual job is compression: proof is sandwiched between hero and offer, never stacked into a wall.
</Accordion>

<Accordion title="Floating track-record cards" icon="orbit">
Eight `<details>` cards positioned absolutely around a central portrait hub inside a 700px-tall relative box, connected by dashed SVG lines at `--color-border-strong`, `stroke-dasharray: 3 5`. Cards are 262px wide, `--radius`, 1px `--color-border`, `--shadow-1`. Summary row is `52px` minimum height: an orange mono year, then a 15px display-weight-650 title, then a 20px circular `+` that rotates 45° and fills orange on open. Open state swaps the border to `--color-brand` and lifts to `--shadow-2`. Below 1080px the whole thing collapses to a plain 2-column grid, the hub becomes a full-width 250px block, and the connector lines are hidden. Build the grid first and layer the absolute positions on top.
</Accordion>

<Accordion title="Problem selector" icon="list-checks">
A self-qualification checklist that reads symptoms and never asks for revenue or headcount. Seven `<button aria-pressed>` rows inside one rounded container, `--radius-lg`, 1px `--color-border-strong`, hairlines between rows. Each row is `56px` minimum, 16px copy at `--color-text-secondary`, with a 22px `6px`-radius box on the left. On press the row background goes `--color-accent-wash`, the text darkens to `--color-text-heading`, the box fills `--color-brand` with a `#7a2a00` border and the tick fades in. A live mono tally sits in the sticky left column. Real buttons with real pressed state, not checkboxes, because the tally has to be keyboard reachable.
</Accordion>

<Accordion title="CTA" icon="mouse-pointer-click">
Primary button: `linear-gradient(180deg, --color-accent-hi, --color-brand)` with a `#7a2a00` 1px border, `--radius-md`, `15px 26px` padding, `52px` minimum height, 16.5px label at weight 650, dark `#180600` text, an inset white highlight plus `--shadow-2`. Hover lifts 1px to `--shadow-3` and nudges the arrow 3px right. Ghost variant is white on `--color-border-strong`. Purple variant exists for secondary paths. The page also carries a sticky bottom action bar on `--color-night` at 96% with a 2px orange top border; below 760px its copy hides and the button goes full width, which is why the nav drops its own button at 720px. One action colour, one action shape, everywhere.
</Accordion>
</AccordionGroup>

**What holds them together.** Three devices, and they are the whole system. A 1px `--color-border` hairline opens and closes every band. An orange mono eyebrow labels every section. Elevation comes only from `--shadow-1`, `-2` and `-3`, and hover moves exactly one step up plus a 1–2px lift. Nothing else may signal depth.

<Step title="One experience figure, applied everywhere" icon="clock">
